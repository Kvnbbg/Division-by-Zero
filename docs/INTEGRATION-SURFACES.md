# Division-by-Zero — integration surfaces\n\n## Current status\n\n| Surface | Current boundary | Confirmation |\n| --- | --- | --- |\n| API | `/v1/**` Spring MVC endpoints | `X-Correlation-Id` is echoed in responses; API errors also expose `correlationId` |\n| Authentication | No authentication endpoint or token issuer is exposed by this service | Do not infer authenticated identity from this API |\n| MCP | No MCP transport/server endpoint is exposed by this service | Agent registry is read-only HTTP metadata, not an MCP server |\n| Errors | Stable `error` + `status` + localized `message` | Error responses carry the request correlation identifier when the filter is active |\n\n## Client rule\n\nClients integrating the current service should:\n\n1. send an optional safe `X-Correlation-Id`;\n2. persist the response correlation identifier for support/debugging;\n3. branch on `error` and `status`, never localized `message`;\n4. treat authentication and MCP as external integration concerns until explicit endpoints/contracts are added.\n\nThis document deliberately records absent surfaces instead of creating fake authentication or MCP compatibility.\n
