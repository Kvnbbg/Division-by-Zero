## États

| État | Définition |
|---|---|
| **OFFER** | L’idée devient une offre formulée. |
| **VALIDATED** | L’offre rencontre une demande réelle. |
| **SOLD** | Une transaction existe réellement. |
| **REPEATABLE** | Le résultat peut être obtenu plusieurs fois. |
| **SYSTEM** | Une partie du processus peut fonctionner sans dépendre entièrement de l’énergie immédiate de son créateur. |

## Transitions

```
IDEA → OFFER → VALIDATED → SOLD → REPEATABLE → SYSTEM
```

- **OFFER → VALIDATED** : preuve de demande (message, précommande, rendez-vous), pas seulement un like.
- **VALIDATED → SOLD** : argent ou équivalent reçu ; pas un « bientôt ».
- **SOLD → REPEATABLE** : même offre livrée au moins deux fois avec un effort comparable.
- **REPEATABLE → SYSTEM** : checklist, automatisation légère, ou tiers qui porte une étape sans que vous soyez sur le créneau.

## Ce que les notes insistent

Distinguer **produits**, **services** et **audience**.  
Prendre en compte : coûts, distribution, paiement, logistique.

Sans ces quatre postes, l’état SOLD reste fragile et SYSTEM n’arrive pas.

## Lien TDAAH

Comme pour la division par zéro : pas de succès silencieux. Un état n’est avancé que s’il est **nommé** et **vérifié** (demande réelle, paiement, répétition). Un « Infinity » commercial (croissance infinie sans mesure) est refusé.
